## 2. 契约逐条（附桌面端实测）

| 契约 | 内容 | 桌面端实测 |
| --- | --- | --- |
| **设置命名空间** | 宿主半以 `SETTINGS_NS = PLUGIN_ID = 'dsh-approval-chime'` 提供配置表单（5 个字段：`enabled / volume / tone / custom / nativeToast`） | 表单字段与默认值经 `host-half` 126 条断言复核 |
| **路由** | 用 `webServer.register` 认领**前缀路由**：`/api/approval-chime/audio`、`/sessions`、`/native-toast` | live：`/sessions` → **200** `{"ok":true,"revision":2,"sessions":{}}`；`/native-toast` → **200** `{"ok":true,"state":"ready"}`；未知路径 → **401** |
| **端口来源** | `lib/native-bridge.js` 用 `setPortSource(() => server.port)` 取端口，写进激活 URI | 端口 19387 **动态**；"回填写死 3080"的旧猜测被推翻 |
| **开关（fail-closed）** | `nativeToast` 默认 `false`；关态下四条 native 子路由一律 `200 skipped/disabled`、**不 spawn 任何子进程**、回填目录不创建也不读取 | 与 `native-toast` 套件 §5/§9 一致 |
| **惰性加载** | native 桥接模块**按需动态 import**，因此第三条路由比前两条晚一个回合认领 | `host-half` 与 `native-toast` 套件都按"等一个回合再数路由"复核 |
| **鉴权兜底** | 未认领路径由 DSH 兜底拒绝 | live 401 |
