## 1. 问题

原来的失败处理把**两种完全不同的结局**混成一个动词：网络/宿主瞬时不可用，与宿主明确回答"这条不用答了"。混在一起的后果是**瞬时失败会丢掉 token**（审批永远不会结算），而"跳过"又会被当成失败反复重试。

## 2. 冻结后的两条语义（契约 §5.1 / §8）

| 情形 | 客户端动作 | 反例（能变红） |
| --- | --- | --- |
| **瞬时失败**（fetch 抛错，如 `the socket is gone`） | 只计数、写诊断、**保留 token**、下一 tick 照常轮询；**不**撤销 | 若实现改成丢 token ⇒ 计数与 token 数都会红 |
| 宿主答 **`skipped`**（例：关态 `{"state":"skipped","reason":"disabled"}`） | **立刻放弃**该 token：不再轮询、**不发撤销**、计入 `skipped` | 若实现改成继续轮询 ⇒ 请求数会涨、token 不会消失 |

## 3. 判定要点

* `skipped` **不算失败**（`failed` 不涨）；瞬时失败**不算跳过**。
* "健康 tick"**不能**把失败计数刷上去。
* 负控都是**行为级**的：改实现即红，不依赖日志文字。
