## A. 审批触发点：能不能在 `ctx.remote.$on('approval/request')` 上插队？

### A.1 结论

| 问题 | 结论 |
| --- | --- |
| `ctx.remote.$on('approval/request', fn, {prepend:true})` 支持 prepend 吗？ | **不支持。`$on` 只有两个形参，第三个参数被静默丢弃。** |
| waterfall 顺序是注册序还是 prepend 优先？ | **两者都生效：带 `prepend` 的监听器插到最前，其余严格按注册顺序（先注册先执行）。** |
| 内置审批面板会不会把请求让给后面的监听器？ | **正常路径不会**——它 `return await pending.result`，不调用 `next()`，因此**在它之后注册的 `$on('approval/request')` 监听器永远不会被调用**。 |
| 推荐方案 | **不要用 `$on`。订阅 `ctx.uiSession.pendingInteractions`（HostObservable），按 `kind === 'approval'` 检测新出现的待审批条目来播放提示音。** |

1. `dsh-web-app` 的 patch 层里就插入了 `ui-approval` 行：`@deepseek-ai/dsh-web-app/cordis.patch.yml` 中

3. 浏览器端 cordis 插件按 entry 树顺序激活（**推断**：客户端 boot 用同一份 loader entry 图构图，`dsh-client-modules/lib/index.js:586-593` 的 `compose()` 保持 entry 顺序；本任务无法启动浏览器实测激活次序）。
4. **更致命的一点**：即使把我们的 bundle 挪到 `dsh-web-app` 之前，我们的 `apply` 也要等 `inject` 的服务（`remote`/`uiSession`/…）就绪才执行，而这些服务由 `dsh-web-app` 里更靠后的行提供——注册时机并不由行序独占决定。**所以「靠行序抢在审批插件前注册」是不可靠的。**

### A.5 备选方案（推荐）：`ctx.uiSession.pendingInteractions`

类型定义 `@deepseek-ai/dsh-client-ui-session/lib/types/client/index.d.ts:96`：

```ts

```

`:29`：`export type SessionPendingInteractionSnapshot = ReadonlyMap<SessionId, SessionPendingInteraction>;`
`:117`：`registerPendingInteraction<T extends SessionPendingInteractionBase>(precedence: (interaction: T) => number): PendingInteractionPublisher<T>;`

**运行时形状（真实实现，可照抄）** `@deepseek-ai/dsh-client-ui-session/lib/client.js:80-90`：


→ 只需要 `getSnapshot()` / `subscribe(listener) → disposer` 两个方法，**不需要 React**。

`<SessionId, PendingInteraction>` 的**approval 条目如何判别**：内置审批面板发布的对象带 `kind`、`key`、`sessionId`（`@deepseek-ai/dsh-client-ui-approval/lib/client.js:114-142`）：


发布时机（`@deepseek-ai/dsh-client-ui-session/lib/client.js:213-227`）：


注意两个语义（写实现时必须照顾）：

* **每个 session 只暴露一个** pending interaction（按 `precedence` 取大者）。同一会话同时有待审批和待回答问题（`dsh-client-ui-user-questions`）时，只有一个会出现在 Map 里。
* Map 每次变化是**整体替换**，元素引用不变（`value.interaction`）。所以要用 `key`/引用做增量 diff，不能「变了就响」。

**为什么推荐它**（相比 `$on`）：

1. 与注册顺序完全无关——不受 §A.4 的行序/inject 时机问题影响。
2. **绝不触碰审批瀑布**：不需要调用 `next()`，不可能因为我们的异常或忘记 next 而卡死审批流程（这是 `$on` 方案的首要风险）。
3. 语义更准确：它在「审批面板真的被呈现给用户」那一刻触发；`$on` 在没有 session 的场合（`answerApproval` 第 238 行 `return next()`）也会触发，而那种情况用户根本看不到面板。
4. 只用公开的服务 + 两个方法（`getSnapshot`/`subscribe`），无 React 依赖。

**退路**（若 `pendingInteractions` 在实测中不可用/不可订阅）：
按优先级依次尝试——(a) `ctx.uiSession` 的服务名/属性若改变，改用 `ctx.remote.$on('approval/request')` 并把本 bundle 排在 `dsh-web-app` **之前**，同时在监听器里**无条件先 `next()` 再播音**（fire-and-forget），接受「可能不触发」而不是「可能卡死审批」；(b) 兜底改为监听 DOM 中审批面板出现（脆弱，不建议）。

### F.4 默认值的时间线（回答「客户端第一次读到之前是什么」）

1. 宿主 `apply` 注册命名空间 → `resolve()` 用 `schema(mergeLayers(base, section))` 立即得到含默认值的解析结果（`dsh-settings/lib/index.js:509-513`）。
2. 客户端首次 `describe` 答复到达前：`mirror.getSnapshot().view === undefined` → scope 维持 `status: 'loading'`、`value: undefined`。**卡片的 `available` 为 false，官方卡片此时渲染 `null`；建议我们同样渲染 null（不要显示占位卡）。**
3. 答复到达且命名空间在列 → `status: 'ready'`，`value` 是宿主解析后的完整对象（默认值已填）。`user` 字段的 **存在性**（不是值比较）才代表「用户覆盖过」——reset 语义靠它（`settings-contract.d.ts:20-25`）。

```js
(function () {
  if (typeof window === 'undefined' || !window.__ModuleLoader__) return;

  window.__ModuleLoader__.load({
    id: 'dsh-approval-chime',                     // 必须等于包名（见 §D.2）

      var PLUGIN_ID = 'dsh-approval-chime';
      var NS = 'approval-chime';                  // = 宿主命名空间 = 卡片 slot 的 key
      var REVISION = 'rev-1';                     // 改行为就 +1：验收时一眼分辨「页面旧」

      /* ---------------------------------------------------------- 提示音 */

      var audio = null;                            // 惰性创建：首次真正要响时才 new
      /** 浏览器自动播放策略：未与页面交互前 AudioContext 处于 suspended。 */
      function ensureAudio() {
        if (audio !== null) return audio;
        var Ctor = window.AudioContext || window.webkitAudioContext;
        if (typeof Ctor !== 'function') return null;
        audio = new Ctor();
        return audio;
      }
      /** 用 WebAudio 合成音；volume 0..100。 */
      function play(tone, volume) {
        var ctxAudio = ensureAudio();
        if (ctxAudio === null) return;
        if (ctxAudio.state === 'suspended' && typeof ctxAudio.resume === 'function') ctxAudio.resume();
        var gain = ctxAudio.createGain();
        gain.gain.value = Math.max(0, Math.min(100, Number(volume) || 0)) / 100 * 0.6;
        gain.connect(ctxAudio.destination);
        var osc = ctxAudio.createOscillator();
        var FREQ = { chime: 880, ping: 1320, beep: 440 };
        osc.frequency.value = FREQ[tone] || FREQ.chime;
        osc.type = 'sine';
        osc.connect(gain);
        osc.start();
        osc.stop(ctxAudio.currentTime + 0.18);
      }

      /* ------------------------------------------------- 审批触发（推荐方案） */

      function watchApprovals(ctx, scope) {
        // ctx.uiSession.pendingInteractions: getSnapshot() / subscribe(listener)
        var source = ctx.uiSession.pendingInteractions;
        var seen = {};
        var sync = function () {
          var snapshot = source.getSnapshot();      // ReadonlyMap<SessionId, PendingInteraction>
          var next = {};
          snapshot.forEach(function (interaction, sessionId) {
            if (interaction === null || typeof interaction !== 'object') return;
            if (interaction.kind !== 'approval') return;      // ← 判别依据（内置实现里 kind === 'approval'）
            var key = typeof interaction.key === 'string' ? interaction.key : String(sessionId);
            next[key] = true;
            if (seen[key] === true) return;

            if (value !== undefined && value.enabled === false) return;
            play(value === undefined ? 'chime' : value.tone, value === undefined ? 70 : value.volume);
          });
          seen = next;
        };
        var off = source.subscribe(sync);
        sync();                                    // 订阅前可能已有待审批：先对齐一次
        return off;
      }

      /* ------------------------------------------------------------ 设置卡片 */

      function Card(props) {
        var t = props.t;
        var snapshot = props.useChime(function (value) { return value; });   // 由 slot 的 inject 提供

          { className: 'dacCard' },

              type: 'checkbox',

              disabled: snapshot.writable !== true,
              onChange: function (event) { setDraft(Object.assign({}, draft || snapshot, { enabled: event.target.checked })); },
            }),
            t('enabled')),
          React.createElement('input', {
            type: 'range', min: 0, max: 100, step: 5,
            value: draft === null ? (snapshot.volume === undefined ? 70 : snapshot.volume) : draft.volume,
            disabled: snapshot.writable !== true,
            onChange: function (event) { setDraft(Object.assign({}, draft || snapshot, { volume: Number(event.target.value) })); },
          }),
          // 「试听」必须在用户手势里调用，才能解除 AudioContext 的 suspended。
          React.createElement('button', { onClick: function () { play(snapshot.tone, snapshot.volume); } }, t('preview')),

            disabled: snapshot.writable !== true,
            onClick: function () {
              if (draft === null) return;
              if (draft.enabled !== undefined) scope.set('enabled', draft.enabled);
              if (draft.volume !== undefined) scope.set('volume', draft.volume);
              setDraft(null);
            },
          }, t('save')),
        );
      }

      /* ------------------------------------------------------------ lifecycle */

      var inject = ['slots', 'settingsScope', 'uiSession', 'locale'];
```

### K.2 采用的注册形态（本仓库 rev-7 的实现）

```js
// lib/client.js（applyInner 内，字典注册之后）
ctx.slots.inject('settings.section', function () {
  return ctx.slots.register(
    {
      name: 'settings.section',
      id: 'approval-chime',   // 自用 id：不撞 general/models/plugins/agent-presets
      order: 16,              // 紧跟「插件」(15)，在「Agent 预设」(20) 之前
      label: navLabel,        // thunk：读 ctx.locale.bind(NS) → 'nav'（zh 通知提醒 / en Notifications）
      locale: NS,             // 令组件拿到 props.t（同一本字典）
    },
    ChimeSection,             // 分区页组件：<h2> + intro + 原控件
  );
});
```

要点：

1. **`inject('settings.section', …)` 等槽被声明**：槽由设置外壳声明，注册发生在回调里，因此「设置外壳尚未挂载」时不会抛错，而是等它出现（工作区先例 `dsh-quorum-panel/lib/client.js:1298-1306` 的注释同义）。
2. **`label` 用 thunk 而不是字符串**：字符串会让导航行冻结在注册时的语言；thunk 每次投影重读（K.1 第 6 行）。
   注意合同正文（`dsh-cordis-client-runner/lib/client.js:3876`）另有一句 *“the registrant re-registers with fresh text on
   locale change, so the shell never subscribes locale state”*——那是更早的写法约定；实现里的 nav store 同时订阅
   slot 账本与 locale revision（`dsh-client-ui-settings-general/lib/client.js:560-582`），因此 thunk 在两种读法下都成立。
3. **标题与导航同文**：字典里 `nav` 与 `title` 取同一文案，页面 `<h2>` 渲染 `t('title')`、导航行渲染 `label()`，两侧不可能漂移；这也是官方三个分区的写法。
4. **列表槽不留 `key`**：`key` 是 keyed 槽（原卡片槽）的配对轴，`settings.section` 用 `id`，不要写 `key`。
5. **降级**：注册整段包在 `try/catch` 里，失败只丢导航行并打印 `[dsh-approval-chime] section registration failed: …`，提示音与其它功能不受影响。
