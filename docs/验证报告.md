| 「不要验证 waterfall 中 `next()` 的通行性」 | **遵守** | 探针只做「不介入」的双向断言（静态 + 运行时 + 差分），不含任何 `next()` 通行性测试。 |

## 7. 残余风险与已知限制（均不构成验收失败）

1. **`inject` 把 `uiSession` 作为硬依赖**（`lib/client.js:1083`）。四个服务名本轮已在 DSH 源码中逐一证实（§5.1 H7），但一旦 DSH 改名/移除，cordis 会因注入未满足而整体不 apply：**提示音和卡片会一起消失**（只在控制台留下 cordis 的等待提示）。这是设计取舍，不是缺陷；若要更保守，可把 chime 监视器与卡片拆成两个 bundle。
2. **去重表上限 256**（`DEDUP_LIMIT`）。被淘汰的 key 若仍留在某次快照里，理论上会再响一次。UI 会话里不可达。
3. **同一次快照里的多个新审批只响一次**（实现注释明示「one chime covers the batch」）。验收要求只规定「同一次审批只响一次」，未要求「多个同时审批响多次」，故不算失败，仅记录行为。
4. **H3 遮蔽**：同会话同时有审批与提问时，审批可能按 precedence 被遮蔽而漏响 —— 已由 DSH 源码证实（probe-5 H3/H3b），属 DSH 限制。
5. **一次鼠标拖拽结束会写两次同一个值**（观测，非缺陷）：`onPointerUp` 与 `onMouseUp` 都在「草稿尚未落地」的窗口内触发提交，probe-3 记录到 `[{"field":"volume","value":60},{"field":"volume","value":60}]`。平台侧写是排队串行的、并携带 `pendingRevision`（probe-5 C.4d–f），被栅栏拒绝时也只是 `recover()` 后 resolve，因此不会出现重复值、也不会弹「设置写入失败」。若要去掉这多余的一次写入，可在 `commitVolume` 里加一个 in-flight 标记（属可选优化，不影响本轮验收）。
6. **U1–U8 未证实项**：按 §8 的人工步骤确认前，不应对外宣称「浏览器里能响」「卡片已出现」「设置已落盘」。

## 8. 需要重启后由用户人工确认的项（交接给 t5 的验收清单）

> ⚠️ **本节是 rev-1 形态的历史清单（t4 加注）**：第 1 项等步骤描述的是「设置 → 可配置插件 → 卡片」。
> **rev-7 起的入口是「设置 → 通知提醒」独立分区**（见 `docs/契约调研.md` §K、`README.md` §3、`docs/挂载与验收.md` §7），
> 且 rev-7 的浏览器侧端到端**仍未证实**（`docs/rev7-独立验证.md` §8）。下面各项的「判据」按 rev-1 阅读。

> 前提：t5 完成挂载（profile `dependencies` 加 `link:`、`dsh.profile.bundles` 追加 `dsh-approval-chime`）并**重启** `dsh web`。以下每项都写清「怎么做、看到什么算通过、看到什么算失败」。

1. **卡片出现（rev-1 形态；rev-7 起改为：设置 → 通知提醒 出现独立一行 + 分区页）**：重启 DSH → 浏览器打开 `http://127.0.0.1:3080`（必须 loopback，见 H12）→ 刷新页面 → 设置 → 可配置插件。**通过**：出现「审批提示音」卡片，右上角 revision 戳显示 `rev-1 · pending-interactions`；滑块默认 70%。**失败**：卡片不出现 → 先看 `settings.yaml` 是否出现 `approval-chime:` 段（判定 DSH 侧是否注册成功），再看浏览器 console 是否有 `[dsh-approval-chime]` 警告。
2. **试听听感**：点卡片「试听」。**通过**：听到短促提示音；卡片「音频状态」变为「已就绪 · 已解锁」。**失败**：无声但状态为「未解锁」→ 先在页面任意处点一下再试（自动播放策略），仍无声则记录 U5。
3. **真实审批触发**：让 DSH 发起一次权限申请（例如执行一个需要审批的工具调用）。**通过**：审批面板出现的同时响一次；卡片「已触发」+1、「上次触发」显示时间、「最近音色/音量」显示 `chime / 70% (gain 0.42)`。**失败**：面板出现但不响 → 记录「已见审批」计数：若计数 +1 而「已触发」不变，则是静音闸门（检查开关/音量）；若「已见审批」也不变，就是 U2 未成立（端到端链路问题），需上报。
4. **不重复响**：在同一个审批未处理期间，让页面发生别的变化（例如切换会话/其他 UI 更新）。**通过**：不重复响。**失败**：同一次审批响第二次 → 去重轴在真实数据上不成立（需上报，本实现按 `key` 去重）。
5. **音量语义**：把滑块拉到 0 → 触发审批（**通过**：不响，卡片出现「因音量为 0 而静音 ×1」）；拉到 50 → 试听（**通过**：明显比 100 小，卡片显示 `gain 0.3`）；拉到 100 → 试听（**通过**：`gain 0.6`）。
6. **开关语义**：关掉「启用提示音」→ 试听按钮变灰、触发审批不响且卡片出现「因『启用』关闭而静音 ×N」；重新打开 → 立即响一次（开启时的即时反馈）。
7. **落盘持久化**：改音量到 35、关掉开关 → 检查 `$DSH_HOME\settings.yaml`。**通过**：出现 `approval-chime:` 段且含 `volume: 35` / `enabled: false`；重启 DSH+刷新页面后卡片仍显示 35%（**通过**：持久化成立）。
8. **审批面板零影响（关键回归）**：连续触发 3 次审批，每次都用面板按钮正常「允许/拒绝」。**通过**：面板按钮立刻生效、无卡顿、无需要二次点击；console 无本插件异常。**失败**：审批卡住/需要重复点击 → 立即回滚（本插件不注册瀑布监听，理论上不可能，但这是最关键的回归项）。
9. **回滚**：profile `dsh.profile.bundles` 移除 `dsh-approval-chime`（或在 profile patch 里 `- id: dsh-approval-chime` + `disabled: true`）→ 重启 → 卡片与提示音同时消失、审批面板照常。
